agent-core architecture

Seven hand-drawn boards of how agent-core works: the durable core, one message end to end, the tools and their rights, code tasks, the connector contract, the prompts, and the live status. They are large fixed-size diagrams: scroll and zoom out.

  1. ArchitectureInbound, the core, outbound; SQLite tables, the scheduler, guardrails.
  2. One Slack message, end to endFrom the websocket to the reply in the thread, step by step, with the tables' columns.
  3. Tools and scopesWho may use what: rights decided by code, checked twice; shared files, remote MCP servers (Notion) and their sign-in.
  4. Code tasksA task, a copy, a branch, a PR; a Claude Code session in its own container; continued later from any conversation.
  5. The Connector contractWhat a connector gives the core, and what each side never does.
  6. Prompts and filesWhich prompt file goes where (reply, triage gate, code task), the memory, and the web view that edits them.
  7. Live statusWhat the agent is doing now: six states pushed on GET /status, and the M5StickC Plus2 that shows them with its face.

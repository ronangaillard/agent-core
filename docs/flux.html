Edge cases
Thread moving during drafting: the reply goes out anyway; the new message gets its answer right after.
Silence: inbox done, outcome silent. Nothing is replayed.
Crash or failure of respond(): on the 2nd pickup, failed and alert. No crash loop.
Crash or timeout while sending: never resent; owner alert.
Re-run after a crash: acted events are re-read, Steve does not redo what it already did.
Transient failure (quota, network): timer retry with backoff, no attempt counted.
The tablesinbox and outbox hold state (status UPDATE); events keeps the history. Every status transition writes its event in the same transaction.

reminders is a mutable table: cancel = DELETE, re-arm = UPDATE. A single timer waits for the next due time; when due, a single transaction creates the system inbox row and re-arms or deletes the reminder. The catch-up cursor lives in the cursors table.

Live status: what the agent is doing, on a small screen
One current state (idle, received, thinking, tool, writing, coding) folded in memory from what the store writes, pushed as Server-Sent Events on GET /status, and shown by an M5StickC Plus2 with the agent's face. Off unless AGENT_STATUS_PORT and AGENT_STATUS_TOKEN are both set. Implemented in src/status.ts and devices/m5stick. No polling: the server pushes, the device listens.
The activity · src/store.ts
store.activity: an EventEmitter every event the store writes (the events table), told as it is written + two moments it does not write, told by the core: thinking a model starts (reply, gate) tool_start a tool starts (its name) { kind, thread_key, author_kind, ref, payload }; nothing more is stored
StatusFeed · src/status.ts · fold(activity) → one Status
received → received (system row: "event") thinking → thinking (the gate: "triage") tool_start → tool (the tool's name) delivering → writing replied · silent · drafted · ignored · intercepted · capped · failed · delivered · delivery_failed · dead → ground task_started → + the task, ground task_waiting · task_failed · task_done · task_abandoned → − the task, ground ground = coding (the repository's name) while a code task runs, else idle; at start: the tasks running a moment with nothing after it (a run cut short, a silent triage): back to ground after 2 min same state, detail and tasks as before: nothing told
GET /status · statusServer() · Server-Sent Events
AGENT_STATUS_PORT + AGENT_STATUS_TOKEN: both, or no server Authorization: Bearer <token>, compared in constant time (else 401; any other path or method: 404) event: status data: {"state":"tool","detail":"notion-search", "tasks":0,"at":"2026-11-15T13:52:07.412Z"} one event at once, then one at each change ": beat" every 25 s: a proxy keeps an idle stream open SIGTERM: the streams are ended with the rest
M5StickC Plus2 · devices/m5stick · Arduino, M5Unified
The agent's face, drawn from its profile picture (26 × 26 cells of 5 px), in landscape (240 × 135), beside a panel that says what it is doing.
• streams GET /status and redraws at once (certs.h: the roots behind Cloudflare's certificates)
• each moment stays at least 1.5 s on screen; the latest one wins
• offline (no Wi-Fi or no stream): the face turns grey; it reconnects alone, waiting longer each time (2 s to 1 min)
• button A or B: brightness, kept across restarts; no sound
• Wi-Fi, STATUS_URL and STATUS_TOKEN in secrets.h, never committed

THE SIX STATES · STATE, DETAIL, WHAT THE SCREEN SHOWS
idle · ground state
no moment going on, no code task running
face: blinks now and then; after 10 min, eyes closed, a "z", the screen dimmed
panel: au repos / dodo
received · a moment
a row enters the inbox; detail "event" for a system row (a reminder, a deployment)
face: wide eyes, the hat's lights flash, a "!"
panel: message !
thinking · a moment
a model call starts; detail "triage" when it is the gate
face: looks up, a light runs along the hat, thought bubbles
panel: cogite (lit: triage)
tool · a moment
a tool starts; detail: its name (memory_read, notion-search…)
face: looks left and right; an icon per tool family (Notion, memory, search, reminder…)
panel: Notion / outil + the tool
writing · a moment
a post is being delivered (the delivering event)
face: the mouth moves
panel: ecrit...
coding · ground state
a code task is running; detail: the repository's name; tasks: how many
face: eyes scan, lights cross on the hat
panel: code + the repository
What it tells, and what it does not
• the detail is a tool's name or a repository's name, never what a message says, who wrote it or where
• nothing is stored: the status is folded in memory; a restart starts again from the tasks still running
• no polling on either side: the store tells each event as it writes it, the server pushes, the device listens
• one bearer token, no account; meant to be reached through a tunnel (Cloudflare), by the device
• the web view (debug.ts) is something else: the tables and the trace, behind a password
